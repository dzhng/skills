# QA Checklist

## Must pass

- The image is 16:9 horizontal.
- The background is clean white.
- Xiaohei appears.
- Xiaohei performs the core action and is not just decoration.
- The composition is a fresh metaphor for the current article, not a copy of an old example.
- The image is weird, creative, and interesting.
- The image is clean and spacious; the main subject stays under roughly 60% of the canvas.
- One image explains one core structure.
- English labels are sparse, short, readable, and correctly spelled.
- No non-English text appears unless the user explicitly requested it.
- Orange is used only for the main path or arrows.
- Red is used only for key points, problems, warnings, or results.
- Blue is used only for secondary notes, feedback, or system state.

## Failure signals

Regenerate or locally edit if any of these occur:

- A top-left title appears, such as “Workflow,” “System Diagram,” “Roadmap,” or “Common Pitfalls.”
- Xiaohei looks like a mascot, meme, or cute cartoon.
- The image looks like a PPT slide, course material, or formal flowchart.
- Too many elements, arrows, or nodes.
- Text turns into long explanations.
- The background has paper texture, shadow, gradient, beige, or noise.
- Realistic UI screenshots or tech-product interface style.
- English spelling errors or unreadable labels.
- The image is too rigid and lacks an absurd metaphor.
- The composition is too similar to `assets/examples/`.

## How to iterate

- Too ordinary: make Xiaohei the action-taker and add a strange but valid metaphor.
- Too complex: remove nodes; keep one action and 3–5 short labels.
- Too cute: emphasize deadpan, blank serious expression, not cute, not mascot.
- Too much like PPT: remove titles, borders, tidy grids, and excessive arrows; turn it into a hand-drawn scene.
- Too similar to an old example: keep the core meaning but change the main object and Xiaohei's action.
- Text is wrong: use a local edit when there are one or two errors; regenerate when there are many errors or too much text.

## Delivery standard

A good image makes the reader think “that’s a little weird,” then understand the structure within one second.

If the first impression is a tutorial page rather than a strange product sketch on blank paper, it does not pass.
